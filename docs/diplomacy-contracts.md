# Chip Diplomacy contract (2026-10-29)

Supersedes V3 for new entry only. Four roles: USA, China, Netherlands, ASML, fixed order. Default 3 rounds, configurable 1–5. Each slot commits one validated action or explicit error/skip. Last round requires decision actions, one per role; failed calls never fabricate final decisions. No numerical economics or network in pure engine.

Engine exports createSimulation({mode,rounds,player}), getObservation(state,role), validateAction(state,action), applyAction(state,action,source), skipAction(state,error), getSnapshot(state). All transitions immutable. State cursor round (1 based), actor (Role), version increments per slot. Sources demo/llm/player. Status running, paused, awaiting_player, completed; server may override for control. Engine exposes awaiting_player when actor===player. Snapshot projects player visibility or public only for observer. Server holds private state.

Action fields per src/diplomacy/types.ts. Government diplomatic proposals target governments; ASML commercial proposals target Netherlands. Statement and decision public with target null. Message private with target required. Proposals bilateral: proposer and recipient; only recipient accepts/rejects existing active proposal, only proposer revises. Revision supersedes original, creates fresh ID and resets consent. Acceptance means simulated internal agreement, never enacts real law. Text never mutates another role's decision. Invalid action does not advance. skipAction records failure and advances. Completed state rejects changes.

Snapshot conforms to types.ts; id assigned by HTTP. Decisions evidence lists actual visible message IDs. Private notes never in snapshot. Observation includes only role's own private notes, scenario, round/rounds, messages visible to role (most recent 24 plus relevant own history), visible proposals, available actions and authority constraints. Private proposal outcomes stay private.

HTTP: GET /api/health -> {status:'ok',llm:{enabled,model}}. POST /api/diplomacy/sessions {mode,rounds,player} -> {id,token,snapshot}. Subsequent calls require Authorization Bearer token: GET /api/diplomacy/sessions/:id -> Snapshot; POST .../:id/step {expectedVersion,action?} -> Snapshot (one slot; 409 concurrent/stale, 422 invalid player action); POST .../:id/control {command:'pause'|'resume'} -> Snapshot; DELETE .../:id cancels/deletes. Client cannot submit state/observations/role/prompts. Pause cancels/discards in-flight output without advancing. Resume reruns current slot. UI auto steps until awaiting_player/paused/completed. Reset deletes session and ignores stale responses.

UI uses fetch, no engine imports; export src/diplomacy/App.tsx. Legacy entry src/main.tsx unchanged. Contract owner coordinator; propose updates instead of breaking it.

Content-depth follow-up: observation.negotiationBrief is a derived, role-visible context aid only: latestVisibleActions (latest actual visible message per role), pendingReceivedProposals, pendingSentProposals, ownRecentActions (up to3), closedProposals. Entries reference actual messages/proposals; no invented beliefs, economics or new writable state. Private profiles contain fictional interests/tradeoffs and remain server-only. Live text targets substantive multi-paragraph responses with concrete conditions and actual historical references; length is guidance, not a rule forcing extra commitments or fabricated outcomes. The public API/action schema is unchanged.

Live-only production update: the user explicitly requires real DeepSeek, no mock. Production UI always creates live sessions; HTTP rejects demo creation403 unless DIPLOMACY_ALLOW_DEMO=true is explicitly set by an isolated offline test/probe process. The deployment script pins this flag false on the public service. Failed live calls remain explicit errors/skips, never replaced with fixtures. No provider credential input or value is present in the frontend.
