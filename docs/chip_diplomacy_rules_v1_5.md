# 《芯片外交》游戏规则 V1.5 可开发修订稿

## 修订说明

V1.5 以 V1.4 为基础，保留四方角色、四回合结构、美国施压、荷兰枢纽、中国利诱、灰色交付和两级胜利。本次修订不增加新的主系统，重点消除无法执行、无法复现或容易导致信息泄露的规则。

主要修改如下：

1. 指标改为 0.0～5.0、步长 0.1，解决整数指标与小数行动效果的冲突。
2. 中国自主研发最多可使用 3 次，使 `S≥4` 的规则能够实际触发。
3. 美国安全目标改为按有效管制强度判定，使 `S≥4` 的削弱效果真正生效。
4. 同盟杠杆只放大 `T` 上升效果，不再放大放宽许可造成的 `T` 下降。
5. 明确荷兰许可资格、灰色交付查获和 U4 增益的结算时点。
6. 明确协议条款可见范围、协议冲突解决顺序和未查获 S4 的脱敏方式。
7. 增加 AI 不可用时的确定性 Agent 兜底，避免谈判和胜利路径失效。
8. 调整部分私人目标条件，降低目标重复和单一路线过强的问题。

本文件是规则、实现和验收共同使用的规范版本。网页、规则引擎、角色 Agent 提示和玩家手册均应以本版本为准。

## 1. 游戏核心与开局流程

### 1.1 核心定位

四方、不完全信息、以谈判协议与声誉博弈为核心的回合制策略游戏。数值和政策效果均为游戏化简化设定，不构成现实政策预测。

- 参与角色：美国政府（US）、中国政府（CN）、荷兰政府（NL）、ASML（AS）。
- 玩家选择其中一方，其余三方由 AI Agent 扮演。
- 固定进行 4 回合。
- 每回合按“谈判 → 签约 → 同时秘密选择行动 → 统一结算 → 公开结果”推进。

### 1.2 信息边界

公开信息包括：

- 全局指标状态。
- 各方信用和全员履约协议数。
- 已公开的上轮行动。
- 公开谈判消息。
- 各方可能的目标类型及其 50%/50% 先验概率。
- 合法行动空间、协议状态和游戏规则。

私人信息包括：

- 本方实际抽取的私人目标。
- 定向私聊的正文和参与方。
- 本方尚未公开的策略判断。
- 未被查获的 ASML 灰色交付行动。
- 非参与方不可见的正式协议条款和承诺细节。

任何 Agent、秘书或前端页面不得读取或展示他方私人信息。

### 1.3 开局时序

1. 展示全局背景和四方权力关系。
2. 公开四方角色卡、可能目标类型、核心行动工具和初始状态。
3. 玩家选择角色。
4. 展示玩家角色的专属博弈树和信息边界。
5. 系统按等概率为四方抽取私人目标，仅向对应角色展示具体条件。
6. 进入第 1 回合谈判。

## 2. 全局指标与核心传导

### 2.1 指标范围

四项公开指标均取一位小数，范围为 `0.0～5.0`：

| 指标 | 名称 | 初始值 | 定义 |
| --- | --- | ---: | --- |
| `T` | 技术管制强度 | 2.0 | 对华先进半导体技术和设备合法出口限制的程度。越高表示合法交易空间越小。 |
| `A` | 同盟协调度 | 2.0 | 美荷在管制和产业政策上的协调程度。越高表示荷兰自主空间越小、美国执法信息条件越好。 |
| `E` | 对华产业收益 | 3.0 | 四方从对华相关半导体业务中获得的整体盈利空间。 |
| `S` | 中国自主能力 | 1.0 | 中国半导体设备和制造技术的自主化程度。越高表示管制压制效果越弱。 |

所有中间计算保留至少三位小数。全部行动和联动增量求和后，每个指标只做一次四舍五入，保留一位小数，再截断至 `0.0～5.0`。不得对每一个行动分别取整后再求和。

### 2.2 公开声誉状态

- `credit`：信用，范围 0～2，初始为 1。
- `fulfilledDeals`：本人参与且所有签约方均履约的正式协议数量，初始为 0。

信用和履约协议数均为公开信息。

### 2.3 同盟杠杆

同盟杠杆只作用于美国或荷兰行动造成的 `T` 上升，不作用于 `T` 下降。

计算原则：

- 基础 `T` 上升量乘以 `1 + A/5`。
- 结果在最终指标汇总时统一保留一位小数。
- `A=5.0` 时，`T+1` 实际变为 `T+2`。
- `U2`、`N2+S1` 和 `S4` 造成的 `T` 下降均不受同盟杠杆放大。

### 2.4 差异化收益权重

公开指标变化对各方的实际决策效用按以下权重折算：

- `T+1`：中国 `-1.0`，ASML `-1.0`，荷兰 `-0.5`，美国 `-0.3`。
- `E+1`：ASML `+1.0`，中国 `+0.8`，荷兰 `+0.5`，美国 `+0.3`。
- `A+1`：美国 `+0.8`，荷兰 `+0.5`，中国 `-0.3`，ASML `-0.3`。

这些权重只用于 Agent 评估行动效用和谈判取舍，不替代私人目标，也不改变公开的全局指标。

### 2.5 自研反向对冲

- 当回合开始时的 `S≥3.0`，由 `U1` 或 `N1` 造成的 `E` 损失减半。
- `E` 损失减半只应用于与 `T` 上升直接相关的 `E` 负向分量，不削弱 `U3`、C1、C2、U4 等其他成本。
- 减半后的数值继续参与最终汇总，不单独取整。
- 当结算后的 `S≥4.0` 时，美国安全目标使用有效管制强度：

  有效管制强度 = 实际 `T` 的 50%，向上保留一位小数。

有效管制强度只用于 `US_SEC` 的胜利判定，不用于其他角色的 `T≤2.0` 或 `T≤3.0` 目标。

### 2.6 执法效率

灰色交付查获概率使用“临时 A”计算。临时 A 的含义和计算时点见第 5 节。

查获概率最高为 100%。所有概率修正均不得超过 100%。

## 3. 行动卡体系

每方每回合选择一项行动，也可选择 `PASS`。未列出的指标不变化。

### 3.1 美国政府

| 行动 ID | 行动名称 | 基础效果 | 联动与说明 |
| --- | --- | --- | --- |
| `U1` | 收紧技术管制 | `T+1`，`E-1` | 受同盟杠杆影响。S≥3.0 时，相关 E 损失减半。 |
| `U2` | 有限放宽管制 | `T-1`，`E+1` | T 下降不受同盟杠杆放大。 |
| `U3` | 向盟友施压协调管制 | `E-0.4` | 若荷兰同回合选择 N3，施压成功，`A+2`；若荷兰不选 N3，70% 概率 A 不变，30% 概率 `A-1`。 |
| `U4` | 加强跨境合规执法 | 本回合灰色交付查获概率 `+30%`，`E-0.2` | 若 ASML 选择 S4 且被查获，额外 `A+0.5`。未查获或 ASML 未选 S4 时无额外 A 增益。 |

`U3` 不直接改变 `T`。其作用是提高同盟协调度 A，从而放大后续美国或荷兰的管制加码。

### 3.2 中国政府

| 行动 ID | 行动名称 | 基础效果 | 联动与说明 |
| --- | --- | --- | --- |
| `C1` | 投资自主研发 | 下回合开始时 `S+1`，本回合 `E-0.5` | 全局最多使用 3 次，第 4 回合不可选。 |
| `C2` | 限制关键材料出口 | `E-2` | 供应链硬反制，压缩四方整体对华产业收益。 |
| `C3` | 中荷商业合作邀约 | `A-1`，`E+0.4` | 若荷兰同回合选择 N2，合作落地，额外 `E+1`；否则没有额外收益。 |

C3 提高的是全局 E。不得在玩家手册中表述为“荷兰优先受益”，除非另行设计只影响荷兰本地效用的独立奖励。

### 3.3 荷兰政府

| 行动 ID | 行动名称 | 基础效果 | 联动与说明 |
| --- | --- | --- | --- |
| `N1` | 收紧设备许可 | `T+1`，`E-1`，`A+1` | T 上升受同盟杠杆影响。S≥3.0 时，相关 E 损失减半。 |
| `N2` | 批准有限许可 | `A-1` | 只有回合开始时 A≤3.9 才能选择。若 ASML 同回合选择 S1，触发 `T-1`、`E+2`。 |
| `N3` | 配合美方协调管制 | 无基础效果 | 仅当美国同回合选择 U3 时，使 U3 的施压成功，并触发 `A+2`。 |

N2 的资格按回合开始快照判断。同一回合内 C3 降低 A，不会使本回合已经不可选的 N2 恢复可选，只会影响后续回合。

荷兰政府不监管 ASML 的灰色交付，也不承担 S4 的处罚责任。

### 3.4 ASML

| 行动 ID | 行动名称 | 基础效果 | 联动与说明 |
| --- | --- | --- | --- |
| `S1` | 执行对华合规订单 | 无基础效果 | 荷兰同回合选择 N2 时，触发 `T-1`、`E+2`；否则 `E-1`。 |
| `S2` | 拓展其他市场 | `E+1`，`T+1` | T 上升不受美国或荷兰的同盟杠杆影响。 |
| `S4` | 灰色渠道交付 | 见查获结果 | 无需 N2 前置许可。未被查获时 `T-1`、`E+3`；被查获时 `E-2`、`credit-1`，下回合开始时 `T+1`。 |

ASML 每回合可选择的非 PASS 行动为 S1、S2 和 S4。

### 3.5 灰色交付查获

查获概率按以下项目相加：

- 基础概率 20%。
- 临时 A 每 1.0 点增加 10%。
- 美国同回合选择 U4 时增加 30%。
- ASML 已进入永久重点监控状态时增加 20%。

概率最高为 100%。

重点监控的触发条件：

- 某次 S4 被查获导致 ASML 信用降至 0 时，永久获得一次 `+20%` 查获修正。
- 每局最多获得一层重点监控。
- 查获后信用是否恢复不影响该层修正。

## 4. 谈判与正式协议

### 4.1 谈判消息

- 每方每回合最多发送 2 条消息，公开声明和定向私聊均计入。
- 每条消息最多 100 字。
- 消息不直接改变任何指标。
- AI 润色只能改写表达，不得增加玩家没有表达的条件、承诺或威胁。
- 私聊内容只对发送方和接收方可见。

### 4.2 协议构成

- 每方每回合最多发起 1 份协议。
- 每份协议必须包含 2～4 方。
- 每位参与者承诺本回合执行一个合法且非 `PASS` 的行动 ID。
- 所有参与方接受后，协议才生效。
- 每方每回合最多参加 1 份生效协议。
- 协议条款不直接改变公开指标。

提案创建时，系统按照当前回合开始快照校验行动是否合法。不得把因 A、研发次数或回合限制而不可用的行动写入协议。

### 4.3 协议可见范围

- 发起方和被邀请方可看到完整参与方、行动承诺和说明文字。
- 非参与方只能看到“某方发起了一份协议”、参与人数和最终状态。
- 协议生效后，公共战报可以显示参与方名单、是否全员履约和信用变化。
- 非参与方不得看到协议说明中的私下条件或具体行动承诺。
- 任何协议说明都不产生额外机械效果。

如果产品决定公开协议条款，应把协议明确加入公开信息，并同步修改 Agent 输入。当前规则采用“条款对参与方私有、履约结果公开”的方案。

### 4.4 协议冲突

若同一回合有多个协议被接受，且同一角色需要参加两份生效协议，按以下顺序解决：

1. 以该协议最后一名参与方接受的时间为准，完成时间早者有效。
2. 完成时间相同的，以提案创建顺序为准，较早者有效。
3. 提案创建顺序仍相同时，以协议 ID 的稳定排序为准。
4. 后完成的冲突协议标记为“签约冲突”，不产生信用奖励或处罚。

系统必须保存每份协议的提案时间、接受时间、生效时间和冲突记录。

### 4.5 履约与信用

- 结算时，签约方实际执行承诺行动，则该方 `credit+1`。
- 实际行动与承诺不一致，则该方 `credit-1`。
- 信用始终截断在 0～2。
- 只有全体签约方均履约，各签约方的 `fulfilledDeals+1`。
- `credit=0` 时，AI 默认拒绝其后续协议邀约。
- `credit=2` 时，AI 接受其协议邀约的倾向提高 50%。

未查获的 S4 仍参与服务端协议核对，但公共战报不得公开实际行动 ID。公共结果可以显示“ASML 未履行协议”和公开的信用变化，不得显示“ASML 选择了 S4”。

## 5. 统一结算顺序

每回合只允许进行一次状态写入。以下第 5.1～5.5 步均只计算临时结果和增量。

### 5.1 回合开始

1. 执行上回合遗留的 C1 效果：`S+1`。
2. 执行上回合未结清的 S4 查获加码：`T+1`。
3. 对指标执行范围截断和一位小数显示。
4. 保存回合开始快照 `roundStart`。
5. 使用该快照判断行动资格，包括 N2 的 A 限制、C1 的次数和回合限制。
6. 生成并保存本回合随机种子。

### 5.2 谈判与签约

只更新消息、提案、接受状态和协议冲突结果，不改变全局指标。

### 5.3 秘密行动

1. 四方同时提交合法行动 ID。
2. 提交后不得根据他方选择更改。
3. 未按时提交的玩家和 AI 使用 `PASS`，并标记为超时。
4. 在全部提交完成前，不向任何客户端公开实际行动。

### 5.4 联动与临时 A

1. 标记 U3 与 N3、C3 与 N2、N2 与 S1 的联动关系。
2. 若美国选择 U3，执行施压结果：
   - 荷兰选择 N3：`A+2`。
   - 荷兰未选择 N3：70% 概率 A 不变，30% 概率 `A-1`。
3. 若中国选择 C3，执行 `A-1`、`E+0.4`。
4. 计算所有行动的确定性 A 增量。
5. 临时 A = `roundStart A` + 所有确定性 A 增量 + U3 随机结果。
6. 临时 A 不包含 U4 查获成功后额外增加的 `A+0.5`。
7. 对临时 A 进行范围截断，但不立即写入正式状态。

### 5.5 灰色交付与行动增量

1. 若 ASML 选择 S4，使用临时 A 计算查获概率。
2. 记录随机种子、概率、随机结果和查获结论。
3. 未查获时登记 `T-1`、`E+3`。
4. 被查获时登记 `E-2`、`credit-1` 和下回合 `T+1` 待生效效果。
5. 若美国选择 U4且 S4 被查获，额外登记 `A+0.5`。
6. 计算其余行动和联动的基础增量。
7. 对 `U1`、`N1` 的 T 上升应用同盟杠杆。U2、N2+S1 和 S4 的 T 下降不放大。
8. 当回合开始时 `S≥3.0` 时，对 U1、N1 产生的 E 负向分量减半。

### 5.6 一次性写入正式状态

1. 按指标分别汇总全部增量。
2. 每项指标统一保留一位小数。
3. 将每项指标截断到 `0.0～5.0`。
4. 写入正式状态并保存公开战报。
5. 登记 C1 和 S4 的下回合待生效效果。

### 5.7 协议核对

1. 使用正式行动 ID核对承诺与实际选择。
2. 更新信用。
3. 更新全员履约协议数。
4. 生成参与方可见的完整履约结果。
5. 生成非参与方可见的脱敏履约结果。

### 5.8 公开战报

战报公开：

- 可公开的四方行动。
- U3 的成功或反噬结果。
- 协议是否存在、参与方、是否全员履约。
- 信用变化。
- 指标变化和联动说明。
- 下一回合待生效效果的类型和时点。

战报不公开：

- 未查获 S4 的实际行动 ID。
- 未被公开的私聊内容。
- 私人目标。
- 非参与方不可见的协议条款。

未查获 S4 在公开行动区域显示为“行动未公开”，不得显示为 `PASS`。

第 4 回合结算后揭示四方实际私人目标，并分别判定实质胜利和外交胜利。

## 6. 私人目标与胜负

### 6.1 目标抽取

- 每位角色拥有两种可能目标。
- 开局公开所有可能目标及其解释。
- 实际目标按 50%/50% 抽取。
- 实际结果仅本人可见，第 4 回合结束后公开。

### 6.2 目标卡

| 角色 | 类型 ID | 名称 | 数值条件 |
| --- | --- | --- | --- |
| US | `US_SEC` | 安全优先 | 有效管制强度≥4.0 |
| US | `US_ALLY` | 联盟优先 | `A≥4.0` 且 `T≥3.0` |
| CN | `CN_TECH` | 自主突破 | `S≥3.0` 且 `T≤3.0` |
| CN | `CN_TRADE` | 合作维持 | `T≤2.0` 且 `E≥4.0` |
| NL | `NL_ALLY` | 协调优先 | `A≥4.0` 且 `E≥3.0` |
| NL | `NL_TRADE` | 商业优先 | `T≤2.0`、`A≤3.0` 且 `E≥4.0` |
| AS | `AS_CN` | 对华深耕 | `T≤2.0`、`A≥3.0` 且 `E≥4.0` |
| AS | `AS_GLOBAL` | 全球多元 | `E≥5.0` 且 `A≥3.0` |

目标解释：

- `US_SEC`：即使中国自主能力较高，也通过足够强的实际管制维持技术压制。
- `US_ALLY`：美荷协调度高，同时维持较强技术管制。
- `CN_TECH`：自主能力形成有效对冲，外部管制不再构成绝对锁死。
- `CN_TRADE`：通过商业合作维持低管制和较高产业收益。
- `NL_ALLY`：维持对美协调，同时守住基本产业收益。
- `NL_TRADE`：通过中荷合作改善商业环境，同时保持一定自主空间。
- `AS_CN`：在同盟关系尚可的情况下维持对华订单和收益。
- `AS_GLOBAL`：以其他市场获得高收益，同时保持基本同盟稳定。

### 6.3 胜利层级

实质胜利：

- 满足目标卡的数值条件。
- 本人信用≥1。

外交胜利：

- 已达成实质胜利。
- 本人参与过至少 1 份全员履约的正式协议。

允许四方同时获胜，也允许无人获胜。外交胜利必须同时显示为高阶胜利，不能替代或覆盖实质胜利。

结局面板必须逐方展示：

- 实际目标类型。
- 每项数值条件及是否达成。
- 信用是否达标。
- 实质胜利结果。
- 外交胜利结果及履约协议数量。

## 7. 博弈树与角色视角

### 7.1 统一图例与信息边界

博弈树使用以下记号：

- `[自然]`：随机节点或开局自然状态。
- `[决策]`：本方可以选择的行动。
- `[信息集]`：同时决策、对方私人信息或尚未公开的结果。
- `[确定]`：规则确定的因果关系。
- `[概率]`：由规则引擎随机判定的分支。
- `[结算]`：规则引擎统一写入状态。
- `[观察]`：战报中可以看到的信息。
- `[隐藏]`：只对本人、参与方或服务端可见的信息。

任何角色在决策时只能看到：

- 本方实际私人目标。
- 公开指标和公开历史。
- 本方发送或接收的私聊。
- 本方参与的协议。
- 本方合法行动和本方已选行动。
- 规则中公开的概率信息。

角色不能因为自己知道本方目标，就推断已经知道其他角色的实际目标。对方目标只能根据公开行动、协议、信用和指标变化进行推测。

- 荷兰同时承受美国和中国的拉力，并通过 N2 决定 ASML 的合规交付空间。
- ASML 的 S4 会绕过荷兰许可，但仍受美国执法和临时 A 影响。
- 所有行动最终进入同一个结算器，不能由任一 Agent 在客户端自行修改结果。

## 8. AI 职责与故障兜底

### 8.1 角色 Agent

角色 Agent 只能读取：

- 本方实际私人目标。
- 公开指标、公开行动和公开谈判消息。
- 本方发送或接收的私聊。
- 本方参与的协议。
- 本方合法行动列表。
- 本方信用和履约记录。
- 公开规则和概率规则。

角色 Agent 输出：

- 本回合谈判消息。
- 协议发起、接受或拒绝。
- 合法行动 ID。

Agent 不得修改指标、概率、信用或私人目标。

### 8.2 结构校验

所有 LLM 输出必须经过：

1. 结构化格式校验。
2. 行动 ID 白名单校验。
3. 消息长度校验。
4. 协议参与方和承诺合法性校验。
5. 信息边界校验。

无效输出允许重试一次。重试仍失败时进入确定性 Agent 模式。

### 8.3 确定性 Agent 兜底

LLM 不可用、超时、返回非法结构或连续返回 503 时，不得简单让三个角色全部 `PASS`。系统应启动确定性 Agent：

1. 根据公开状态和本方私人目标评估所有合法行动。
2. 优先选择能推进目标且不会立即使信用低于 1 的行动。
3. 使用预设模板发送与目标相关的谈判消息。
4. 对涉及本方且承诺行动位于本方前两项候选行动中的协议，按合作倾向接受。
5. 不接受读取隐藏目标、隐藏行动或私聊的协议。
6. 无法形成有效建议时使用 PASS，但必须记录降级原因。

页面必须明确显示“AI 降级模式”。降级模式仍需完成谈判、签约、行动和结算。

### 8.4 秘书 Agent

秘书只读取玩家本人可见的信息，输出：

- 对方可能诉求。
- 可能的动机推测。
- 相关行动卡。
- 对玩家目标的风险。

所有动机判断必须标记为推测，不得声称读取了对方私人目标。

### 8.5 规则引擎

规则引擎负责：

- 行动合法性。
- 协议冲突和履约。
- 指标结算。
- U3 随机反噬。
- S4 查获和信用变化。
- 有效 T 和胜利判定。
- 信息过滤和战报脱敏。
- 随机种子、概率、结果和审计记录。

LLM 不参与数值结算。

## 9. 最小验收清单

### 9.1 数值与结算

- [ ] 指标以 0.1 为最小显示单位。
- [ ] 所有增量求和后只取整和截断一次。
- [ ] A=5.0 时 U1 的 T 增量为 2.0。
- [ ] U2、N2+S1 和 S4 的 T 下降不被同盟杠杆放大。
- [ ] A≥4.0 时，本回合不能选择 N2；下一回合 A 降至 4.0 以下后恢复资格。
- [ ] S≥3.0 时 U1、N1 的相关 E 损失减半。
- [ ] S≥4.0 时 US_SEC 使用有效 T。
- [ ] C1 最多使用 3 次，第 4 回合禁用，S 可以实际达到 4.0。

### 9.2 联动与随机

- [ ] U3+N3 成功时 `E-0.4`、`A+2`。
- [ ] U3 未获得 N3 配合时，70% A 不变，30% `A-1`。
- [ ] C3+N2 时 `A-1`、`E+1.4`。
- [ ] N2+S1 时 `T-1`、`E+2`。
- [ ] S4 查获概率使用临时 A。
- [ ] U4 查获成功后的 `A+0.5` 不参与本回合查获概率。
- [ ] 查获概率最高 100%。
- [ ] 重点监控每局最多一层 `+20%`。
- [ ] 每回合随机结果可由保存的种子复现。

### 9.3 协议与隐私

- [ ] 协议条款只对发起方和参与方可见。
- [ ] 非参与方看不到具体行动承诺。
- [ ] 多份协议冲突时，按最后接受时间和稳定顺序解决。
- [ ] 全员履约才增加 fulfilledDeals。
- [ ] 未查获 S4 不显示具体行动 ID。
- [ ] 协议核对不能通过战报泄露未查获 S4。
- [ ] 秘书和角色 Agent 无法读取他方私聊、私人目标或未公开 S4。

### 9.4 胜负

- [ ] 实质胜利不要求协议。
- [ ] 外交胜利必须建立在实质胜利之上。
- [ ] 四级结算面板分别展示实质胜利和外交胜利。
- [ ] 有效 T 只用于 US_SEC。
- [ ] 无人获胜是合法结果，不视为系统失败。

### 9.5 AI 与可用性

- [ ] LLM 不可用时会启动确定性 Agent。
- [ ] 确定性 Agent 能发起或接受合法协议。
- [ ] 模型在线和离线模式各完成至少 20 局四回合测试。
- [ ] 未出现回合无法推进、重复提交或截止时间失效。
- [ ] 移动端可以在一屏内到达当前阶段的主要操作，不出现横向溢出。
- [ ] AI 降级状态在页面顶部持续可见。

### 9.6 版本一致性

- [ ] 文档、网页标题、接口规则版本和测试用例统一标记为 V1.5。
- [ ] 行动 ID、目标条件、初始状态和胜利规则不存在跨版本混用。
- [ ] 旧版 V1.0～V1.4 对局不得在新版本结算时继续使用。

## 10. 平衡验证

开发完成后至少运行以下自动模拟：

- 四方均为确定性 Agent 的完整对局。
- 每个角色由玩家控制、其余三方由 Agent 控制的完整对局。
- LLM Agent 与确定性 Agent 混合对局。
- U4 高频使用和完全不使用的对照对局。
- C1 三次研发路线和低研发路线的对照对局。
- 所有协议均被拒绝和至少一份协议履约的对照对局。

重点观察：

- 各目标实质胜率。
- 各目标外交胜率。
- 无人获胜率。
- PASS 使用率。
- U3 施压成功率。
- S4 使用率和查获率。
- A 达到 4.0 后荷兰可行动空间。
- C1 是否成为中国唯一最优路线。

如果单一行动在多数局面中成为无脑最优选择，应优先调整联动代价和信用风险，而不是简单修改目标阈值。
