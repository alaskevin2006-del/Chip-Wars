# 《芯片博弈：技术封锁与供应链重构》设计基线 v3.0

> **状态：供 MVP 开发使用的冻结基线**｜**日期：2026-10-27**｜**截止：2026-10-31 23:59（北京时间）**  
> **性质：**基于真实政策与产业机制抽象的**虚构近未来回合制策略游戏**，不承担政策预测、实证因果识别或对现实行为体评分的功能。  
> **使用方式：**这是开发与验收的单一规格来源。历史版本 `v1` / `v2` 中与此文冲突的内容，以本版为准。开发过程中的数值调优可更新配置，不应随意扩张机制。

## 0. 交付边界和不可变原则

| 项目 | 冻结要求 |
|---|---|
| 玩家 | 单人选择 **美国政府或中国政府**；其他角色由决策器控制 |
| 对局 | **6个回合**，每回合一个抽象政策周期；1个标准开局，虚构2027年起的产业局势 |
| 决策主体 | **9个Agent**：5个政府、4个企业（见§1） |
| 非Agent实体 | ASML、日本/美国设备商、韩国存储企业及HBM、监管模块、材料供给作为**规则驱动模块**，不能是静态常数 |
| 核心玩法 | 有限行动点/资金 → 各方选择 → 法律和产业规则结算 → 信息反馈 → 下轮选择 |
| 结局 | 分阵营的**多目标绩效与结局标签**；不宣称现实中的国家“胜负” |
| 核心实现 | **React + TypeScript（Vite）**；纯TS游戏引擎，规则Agent作可靠兜底；少量LLM通过**可选后端代理**接入 |
| 必需AI使用 | 用Codex/生成式AI参与作品开发；**争取接入1个LLM对手**增强交互，但游戏不得依赖在线模型才能运行 |
| 时间优先级 | **P0：可完成六轮的规则版** → **P1：可视化与1个LLM** → **P2：回滚/复杂外交** |

**通用约束，只在此定义：**

1. **权限边界**：政府只能改变自己有权管理的政策；企业只能在合法范围内交易和投资；美国外交不能直接替荷日作决定；韩国不能豁免美国许可证；台积电不能以商业决定绕过中国台湾地区或其他适用法规。
2. **策略与结果分离**：Agent只提交**行动意图**，环境引擎计算结果；自然语言不能直接改写数值。
3. **资金守恒式记账**：政府补贴为政府预算减少、受益企业现金增加；企业研发/投资再消耗企业现金。不能“补贴直接+技术能力”并同时“企业研发再次+技术”。
4. **时间与瓶颈**：管制对**新增合法供给**立即生效，但不会抹去已安装设备；研发、替代投资、建厂有延迟；设计、晶圆制造、良率、封装和HBM分别受约束。
5. **学术边界**：资料支持**因果方向/制度约束**，**不证明游戏系数、隐藏偏好权重、成功率**。所有数值统一标记为游戏假设 `[G]`，政策与产业方向标记 `[E]`。
6. **因果可追踪**：每轮引擎记录“行动 → 规则 → 状态差值 → 角色回报”，战报不得杜撰变化。

## 1. Agent与非Agent的最终边界

### 1.1 九个决策Agent（稳定ID）

| Agent ID | 实体 | 核心目标（不是实证严格排序） | 可操纵范围／关键约束 |
|---|---|---|---|
| `US_GOV` | 美国政府 | 技术安全、国内竞争力、财政、盟友协调 | 本国芯片/设备许可、产业扶持、外交；无法强制盟友或企业研发成功 |
| `CN_GOV` | 中国政府 | 可用算力、国产有效产出、企业生存、财政与反制代价 | 镓锗许可、产业补贴、国产供给协作、缓和提议；无法直接生产芯片 |
| `NL_GOV` | 荷兰政府 | 技术安全、本国光刻产业、监管自主、合作关系 | 荷兰管制范围内的DUV许可、本国产业支持；承受ASML收入与外交反馈 |
| `JP_GOV` | 日本政府 | 经济安全、本国设备产业、外交协调、企业收益 | 日本对应设备/材料许可、产业支持；与荷兰作用于不同制造环节 |
| `KR_GOV` | 韩国政府 | 安全协调、存储产业竞争力、在华经营稳定 | 支持存储产业、对美协调争取在华经营空间；不得单方面改变美国管制 |
| `US_AI` | 美国AI芯片设计企业（合成） | 合规、利润、技术领先、市场布局 | 合规供货、研发、游说；依赖第三方代工与HBM，不拥有制造产能 |
| `CN_DESIGN` | 中国AI芯片设计企业（合成） | 产品交付、设计能力、资金、制造与封装适配 | 设计研发、国产工艺适配、封装协作；设计成功不等于可量产 |
| `CN_FAB` | 中国晶圆制造企业（合成） | 有效产出、良率、工艺能力、现金流 | 设备购置、工艺与良率投资、产能分配；受现存设备、许可和工艺约束 |
| `TSMC` | 台积电（企业Agent，抽象经营） | 合规、长期利润、客户履约、先进制造能力 | **仅在合法、可调整的少部分产能**中配置订单、规划扩产；已承诺产能不可随意重分配 |

- **玩家只接管 `US_GOV` / `CN_GOV` 中的一个**，两个政府始终存在；被接管者停用AI决策而直接读取玩家行动。
- 企业可使用合成画像，不把现实企业的收入、偏好精确映射成游戏数值。
- 各Agent的隐藏偏好为游戏类型 `security / industry / balanced` 等权重向量（和为1）；**法律合规属于硬约束，不参与权重竞争**。

### 1.2 必须存在、但不独立调用LLM的世界模块

| 模块 | 要有的动态行为 | 影响路径 |
|---|---|---|
| `NL_LITHO` | 按荷兰许可、订单、交付能力变更合法DUV交付和ASML收益；商业损失形成荷兰国内压力 | 荷兰政策 ↔ 光刻交付/收益 ↔ 荷兰下轮收益权衡 |
| `JP_US_TOOLS` | 美、日设备许可分别约束不同类别新增设备；维护现有存量 | 设备供应 ↔ 中国工艺与产出瓶颈；日企收益 ↔ 日本政府 |
| `KR_MEMORY` | HBM供给、韩国存储利润、在华工厂经营和投资随需求及许可变化 | 韩国扶持/美国许可 → 企业收益及HBM能力 → 韩国下轮决策 |
| `TW_REGULATION` | 固定的合规掩码/适用规则，明确部分交易不可做 | 台湾地区相关监管、适用出口许可 → TSMC可执行订单 |
| `GA_GE_MARKET` | **镓和锗独立计算**合法出口、库存、材料替代、相关行业成本、中国出口机会损失 | 中国材料政策 → 特定下游部门成本 → 外国替代投资、政府成本权衡 |
| `PACKAGING` | 中国封装能力和HBM供给分开记录，配套投资可有限改善封装能力 | 国内产出瓶颈；不能被设计研发一键消除 |

**不建立**中国台湾地区政策管理方、ASML、韩国存储企业等更多自主决策Agent。上述模块可以采用**规则性响应**，不是不变的背景数字；如赛后扩展，再升级为Agent。

## 2. 行动空间：24类行动模板 + 维持现状

**约定：**美国、中国政府各回合最多 **2 AP**；荷兰、日本、韩国政府各 **1 AP**；四个企业各 **1 AP**。同一政策回合最多改变一级；企业行动应检查现金和合法性。每个行动模板中的目标可以参数化，**不为每个目标复制新机制**。`维持现状` 不花AP。具体费用和等级映射放配置表，不写死在代码里。

| 执行者 | 行动模板（目标或选项） | 直接作用的状态／中介 |
|---|---|---|
| `US_GOV` | `US_CHIP_LICENSE`：芯片许可±1 | 法定供给边界 → 中国合法进口、美国企业收入 |
| | `US_TOOL_LICENSE`：美源制造设备许可±1 | 其他关键设备新增合法交付 |
| | `US_DIPLOMACY`：协调荷/日/韩之一 | 目标政府的协调收益/外交关系，不强制其复制政策 |
| | `US_SUPPORT`：本土研发/材料替代二选一 | 本国财政、受扶持产业；材料替代进入延迟队列 |
| `CN_GOV` | `CN_MATERIAL_LICENSE`：镓/锗之一许可±1 | 对应资源的合法供给、出口收入、战略信号 |
| | `CN_SUBSIDY`：设计/制造/封装协作之一 | 政府预算向指定受益企业转移，企业自行决定投资 |
| | `CN_INDUSTRY_COORD`：国产供应链协作 | 降低适配/交易摩擦，耗费预算或AP，不直接增加设计能力 |
| | `CN_OFFER`：提出预设缓和邀约 | 产生可接受/拒绝的有限条件提议，不自动修改对方政策 |
| `NL_GOV` | `NL_DUV_LICENSE`：荷兰受控DUV许可±1 | 合法DUV新增交付、ASML损益 |
| | `NL_SUPPORT`：本国光刻产业支持 | 荷兰预算、产业适应/收益 |
| | `NL_COORD`：协调/强调自主监管 | 美荷关系和本国政策收益；许可仍是独立动作 |
| `JP_GOV` | `JP_TOOL_LICENSE`：日本受控设备许可±1 | 相关制造设备新增供给、日企经营 |
| | `JP_SUPPORT`：本国产业支持或保供 | 日本预算、合法供货及本国产业韧性 |
| `KR_GOV` | `KR_STORAGE_SUPPORT`：存储产业/HBM支持 | 韩国预算、HBM未来有效供给、韩企商业收益 |
| | `KR_FAB_DIPLOMACY`：向美方争取在华工厂许可便利 | 美韩协调/美方判断，不会立刻绕过美国许可 |
| `US_AI` | `US_AI_MARKET`：合法对华/其他市场订单与产品组合 | 合规订单、短期利润；须受代工和HBM约束 |
| | `US_AI_RD`：技术研发投资 | 企业现金、未来技术竞争力（延迟） |
| | `US_AI_LOBBY`：对美方政策游说 | 企业现金、美国国内政策压力（非强制） |
| `CN_DESIGN` | `CN_DESIGN_RD`：设计能力研发 | 企业现金、未来设计能力 |
| | `CN_DESIGN_COORD`：制造适配/封装协作二选一 | 适配系数或**国产封装能力**的延迟改善 |
| `CN_FAB` | `CN_FAB_INVEST`：工艺/良率/国产设备适配之一 | 企业现金、未来工艺/良率/设备可用性 |
| | `CN_FAB_ORDER`：合规设备采购及产能配置 | 新增合法设备、制造成本与当期可交付产能 |
| `TSMC` | `TSMC_ALLOCATE`：合法客户间重新分配**灵活产能** | 美国AI企业实际可获得代工、台积电收入；约束客户合同 |
| | `TSMC_CAPEX`：投资先进产能/海外布局 | 企业现金、若干轮后的产能及布局分布；合规不随投资消失 |

> **细节校验：**上表是24类核心行动模板；“企业日常正常经营/已有合同履约”由引擎自动处理，不需要每次花AP才发生。`CN_OFFER` 的接受/拒绝由对方政府在下一次有行动权时处理；首版若谈判未开发完，隐藏该行动卡而不影响核心六轮游戏。`TSMC` 不能向被禁止的买方分配产能。

### 2.1 资源成本和动作可预期性

- 每个行动声明：`id, actor, target, ap_cost, money_cost, preconditions, effective_at, duration, explanation`。政策等级按 `[0,1,2]` 表示相对宽松、审核、严格（**仅游戏概念，不是官方审批概率**）。
- 对有跨回合效果的动作，UI显示**方向、受影响节点、预计延迟和风险**，而非未经计算的百分比。
- 国内产业补贴占用财政，企业自行决定研发；企业研发需现金；策略冲突不能靠无成本的卡牌突破。
- **避免末轮废牌**：在第5、6轮，不具现实回报的2轮延迟投资需要显示“仅计入长期潜力”或禁止执行；结局可有限计入未兑现项目的折现潜力，明确不当成现实产量。

## 3. 环境状态：一套状态字典，不为画面重复维护数值

`WorldState` 只存底层状态，`Indicators` 由状态派生计算；相同数据只在一个位置维护。大多数连续量使用 **0–100游戏指数**（不得把不同物理含义的指数直接相加）；财政、企业现金、库存、投资队列单独记账。分组如下：

| 组 | 持久化字段（推荐命名） | 作用 |
|---|---|---|
| 政策 `policy` | `us_chip`, `us_tool`, `nl_duv`, `jp_tool`, `cn_ga`, `cn_ge`（各0..2）；`tw_compliance_mask`, `us_fab_license_scope`（情景给定） | **合法性门槛**；韩国在华工厂的美源设备许可属于美方规则，韩国不能改此字段 |
| 技术及设备 `technology` | `cn_design`, `cn_process`, `cn_yield`, `cn_packaging`, `cn_tools_litho`, `cn_tools_other`, `cn_local_tool_adaptation`, `us_ai_frontier` | 分开记录设计、制造、设备、封装、领先技术；研发更新这些基础量 |
| 上游供给 `capacity` | `tsmc_total`, `tsmc_flexible_share`, `tsmc_us_ai_allocation`, `global_hbm`, `cn_hbm_access`, `kr_china_fab_operability` | 台积电有限灵活产能；HBM与在华韩企经营分别反馈，不等于韩国政府直接审批许可 |
| 材料 `materials` | `ga`、`ge` 各自的 `inventory`, `licensed_supply`, `non_cn_alt_capacity`, `affected_sector_demand` | **材料用途定向**；存量先缓冲短缺，国外替代项目延迟进入产能 |
| 财务 `finance` | `government_budgets[5]`, `firm_cash[US_AI,CN_DESIGN,CN_FAB,TSMC]`, `firm_profit[...]`, `industry_profit[NL,JP,KR]`, `cn_material_export_revenue` | 记录政府预算、每家企业现金与利润，规则企业模块也要有经营结果 |
| 政治与信号 `politics` | `alignment[US_NL,US_JP,US_KR]`, `domestic_pressure[US,NL,JP,KR,CN]`, `offers` | 区分政府安全/外交姿态与法律管制、未禁贸易活动；压力只进入决策效用 |
| 后续事项 `timeline` | `turn`, `pending_projects`, `history`, `external_shocks`, `seed`, `rng_state` | 实现延迟项目、复盘与可复现结算 |
| 私有信息 `private` | `weights[agent]`, `strategy_type[agent]`, `private_estimates[agent]` | 不直接展示给其他Agent；场景参数并非真实行为体“真实心理” |

**派生指标只计算、不得反向直接赋值：**

- `cn_legal_ai_import`：合法芯片供给（由政策、订单、代工、HBM共同约束）；
- `cn_domestic_ai_output`：国产AI芯片**有效交付**（设计/制造/良率/设备/封装/HBM组合瓶颈）；
- `cn_usable_ai = min(demand_cn, cn_legal_ai_import + cn_domestic_ai_output)`；
- `ga_sector_cost`, `ge_sector_cost`：分别对应实际使用镓、锗的国外相关下游部门；
- `us_exporter_loss`, `nl_litho_profit`, `jp_tool_profit`, `kr_memory_profit`：来自合规交易与相关投资/收入变化；
- `supply_chain_risk`, `dependency_index`, `player_score`：综合展示/评分结果，不再反过来重复干预基础供给公式。

**不能省略的产业边界：**

- 设备许可先限定**合法新增交付**，现存设备只会因维护、损耗等独立机制变化；美、日、荷设备类别不能简单三次给同一节点乘同一惩罚。
- **芯片设计 ≠ 晶圆制造 ≠ 良率 ≠ 先进封装 ≠ HBM供给**。限制条件必须允许玩家通过不同投入逐步改善，但不保证六轮内完全解决。封装投资不会凭空制造HBM。
- **镓、锗分离建模**，作用于确实使用相应材料的部门；不得设置“镓出口受限→硅GPU立刻减产”。
- TSMC是代工企业，先进芯片供给需来自真实的订单/产能/合规交集；不能用一个研发按钮生成额外订单和产能。

## 4. 规则引擎：六条结算机制

所有函数使用固定的 `GameConfig` 参数；公式仅确定**结构与方向**，系数由配置设定 `[G]`，优先实现连续、小幅、可解释的变化。

| 机制ID | 输入 → 引擎计算 → 输出 | 必须实现的反馈 |
|---|---|---|
| `M1_LEGAL_TRADE` | 各国许可和合规掩码 + 合法订单 + 各企业供给意愿 + 台积电/HBM上限 → **实际合法交付与利润** | 管制阻断部分供给，同时形成有关企业商业损失；不允许违规交易换取利润 |
| `M2_TOOLS_FAB` | 荷兰DUV、美日其他设备许可 + 合法新增设备 + 既有设备/维护 + 中国工艺、良率 → **国产有效产能瓶颈** | 限制新增设备、制造扩张；存量仍在运转；国内替代与良率可改善部分瓶颈 |
| `M3_RD_PIPELINE` | 政府补贴转账 + 企业现金投资 + 配套条件 + 研发队列 → **延迟能力积累** | 补贴不自动研发；研发不自动成功；制造与封装投资不等于设计能力 |
| `M4_MATERIALS` | 中国镓/锗许可 + 国外库存 + 非中国产能 + 相关部门需求 → **材料缺口、对应部门成本及中国出口机会损失** | 当轮材料施压可能有效，数轮后替代投资削弱杠杆；不直接修改硅GPU产量 |
| `M5_GOV_FIRM` | 企业利润、产业损失、游说/外交动作 → **本国政策压力、政府效用、盟友协调** | 经济损失与国家安全目标冲突；游说非强制；盟友独立决定许可 |
| `M6_SUPPLY_ALLOCATION` | 台积电已有合同 + 有限灵活产能 + 合规订单 + 全球HBM/封装 → **各市场实际可交付先进AI芯片** | 政策改变订单可达性；TSMC只分配灵活份额，扩建滞后；中美不能直接命令台积电违规销售 |

### 4.1 结算顺序与可计算关系

1. **政策/许可门槛**：先检查适用司法辖区和产品类别，明确不合法的交易量为0。其余交易还需满足实际订单和供给约束。不能把受控类别的许可证审批率当作现实百分比；游戏可用0/1/2映射抽象通行能力。
2. **市场清算**：对各个产业环节建立供需上限，合法交付取 `min(需求, 合法供给, 相应产能/配套)`；TSMC承诺合同先满足，再在可调整产能内分配。
3. **存量更新**：`设备次轮存量 = 本轮存量×可用率 + 本轮合法新增设备 + 有效的本土适配供给`；库存相应地 `期末库存 = 期初库存 + 合法入库 − 实际消耗`（全部截断为非负）。
4. **国内有效产出**：先将设计、工艺/良率、设备、封装、HBM等分别换算为**同一交付量指数**，再以瓶颈函数（首版可取`min`）形成实际交付；不得将“良率%”直接和“设备数量指数”取最小值。
5. **研发项目**：企业支付现金后将项目加入 `pending_projects{owner, target, invest, due_turn, expected_range}`；到期按配套条件、折减投入、固定种子随机扰动累积能力。不能用当期补贴立即增加技术指数。
6. **材料影响**：对镓与锗分别计算库存和替代供给抵扣后的短缺，再影响**相关部门**成本；由该部门损益和企业游说影响政府压力；国外材料替代项目需付现并在未来生效。
7. **财务、政治和评分**：对已经产生的交易、投资、利润、补贴与外交影响记账；政府综合评分与企业效用在**结算后**读取状态，不应再返回引擎重复修改当期经济流量。

### 4.2 资源与结局

- 政府预算、企业现金**分账户**；任何资金变动应同时产生收支日志。为保证6轮可玩，政府可按预定义情景获得小额常规财政补充，企业由实际经营获得现金流，禁止无条件补满。
- 参与方收益采用 `score_i = Σ(weight_i[k] × normalized_dimension_k) − risk_cost`。每一类维度先归一化，玩家自身政府的胜利维度公开，对手权重隐藏。[G]
- 玩家最终查看：技术/算力、经济、外交、财政（阵营不同可采用不同含义），以及可解释的结局标签（如技术遏制伴随商业损失、长期自主化但财政紧张、有限缓和等）。**不输出对现实国家的价值评判或真实政策建议。**

## 5. 完整单回合协议及信息边界

| 阶段 | 发生的事 | 能看见什么 |
|---|---|---|
| `S0_BRIEFING` | 公布上轮政策与经结算的世界状态；显示行动点、预算和合法行动 | 公共政策与行业趋势；各自私有偏好只对本Agent开放 |
| `S1_MAJOR_GOV` | **中美同时封闭提交**，玩家控制其中之一，另一政府决策器独立决定 | 另一方不能提前读取玩家本回合尚未公布的选择；齐备后统一公布 |
| `S2_THIRD_GOV` | 荷、日、韩在看到中美本轮已公布政策后分别决策 | 依据自己的国内产业情况与合法动作；外交影响收益但不直接控制其动作 |
| `S3_FIRMS` | 四家企业在当前政策下独立提交订单意愿、研发/投资、游说等行动 | 企业看到公共规则与自身私有业务数据；不偷看竞争者当轮封闭动作 |
| `S4_RESOLVE` | 引擎统一执行M1—M6、费用和延迟项目更新、固定种子外生事件，形成回合日志 | Agent不能参与改写已结算数值 |
| `S5_REPORT` | 战报：每个行动、状态变化、直接和间接原因；更新可见的对手倾向线索 | 下一轮仅提供自己有权看到的信息；玩家可选择继续 |

- **谈判的MVP实现**：`CN_OFFER` 提交一份结构化预设邀约，记录为 `pending_offer`；被邀请方在下一次有权行动时接受/拒绝，只有各方同意且合法时才执行政策调整；首版不允许AI自由签订不限内容的协议。
- **不完全信息的MVP实现**：引擎持有各Agent真实游戏参数；Agent收到 `observe(world, role_id)`裁剪出的局势，可附简化的“强硬/审慎/商业导向”等基于历史行动的**可错判断**；不要求训练模型或精确贝叶斯概率。
- **随机性与复盘**：同一状态、合法动作、配置与显式随机输入产生相同结算。LLM决策本身**不保证固定种子重现**；原路线回放使用保存的Agent决策，分支重算则允许新策略出现，外生事件优先重用已生成的事件序列。

## 6. Agent决策规则与LLM接入

### 6.1 对所有Agent相同的接口

```ts
type AgentObservation = {
  roleId: string;
  turn: number;
  phase: string;
  publicState: Record<string, unknown>;
  privateState: Record<string, unknown>;
  history: EventSummary[];
  legalActions: LegalAction[];
};

type AgentDecision = {
  actions: Array<{ id: string; target?: string; level?: number }>;
  rationale?: string; // 只用于战报，不能修改状态
};
```

统一流程：`observe → legalActions → decide(rule 或 LLM) → validate → resolveTurn`。

- **规则Agent（P0）**：每种Agent设置不同隐藏偏好类型；在合法行动中模拟一步可预期收益，使用确定性加权评分和有种子的小幅扰动选动作。重点是独立效用和合法性，不追求复杂最优策略求解。
- **LLM Agent（P1）**：首选对手中/美政府，第二优先第三方关键政府。Prompt只给自己的 `AgentObservation` 与输出Schema。若输出无效，最多重试一次，再退回规则Agent；必须设置超时。
- **政策描述/战报AI**：可以使用固定模板，LLM润色只能引用引擎已生成的 `delta/effects`，不允许创造新的数值、假动作、事实结论。
- 若整局运行在浏览器内，私有偏好只对界面和Agent接口**逻辑隔离**，不能抵抗用户打开开发者工具；如未来需要可信隐藏状态/联网多人，迁移到服务端持有权威状态。

## 7. 技术架构与最小数据契约

**冻结技术路线**：`React + Vite + TypeScript + 纯TS引擎`；不强制FastAPI、数据库、Mesa、MiroFish、LangGraph。先做**纯浏览器可完成六轮对局**；实时LLM需要时加入**轻量后端代理**，API密钥仅由服务端持有。存档可先用浏览器本地持久化和JSON导出。

```text
src/
  engine/
    types.ts            # 唯一的数据类型定义
    config.ts           # 游戏参数及开局
    actions.ts          # 行动清单、合法性检查、AP/资金验证
    mechanics.ts        # M1—M6，统一结算函数
    turn.ts             # 阶段调度
    scoring.ts          # 分项收益与结局
    observation.ts      # 各Agent可见信息投影
    rng.ts              # 显式种子随机数
  agents/
    rule.ts             # 永远可用的基线决策器
    llm.ts              # 可选调用服务端代理
  ui/
    StartScreen.tsx
    GameScreen.tsx
    ReportScreen.tsx
    EndingScreen.tsx
  tests/
    engine.test.ts
    agents.test.ts
    smoke.test.ts
```

最低API契约：

```ts
createGame(config, seed, playerRole): WorldState
getObservation(state, role): AgentObservation
getLegalActions(state, role): LegalAction[]
validateDecision(state, role, decision): ValidationResult
resolveTurn(state, decisions, randomInputs, config): { nextState, events, indicators }
```

**原则：** `resolveTurn()` 不调用模型、不直接接触UI/网络、不修改入参状态。所有主界面数字和战报只来自 `nextState/events/indicators`，不设第二份可编辑状态。

## 8. MVP UI（四屏，其他效果都让路）

1. **开局页**：选择中国/美国政府，说明虚构游戏、目标、回合数，启动标准场景。
2. **政策页**：显示预算/AP、当前合法政策、24类行动中本角色可用的卡牌；核心仪表盘（技术/供给、利润、材料与外交）和简化产业链瓶颈图。
3. **战报页**：逐角色已执行行动；每一项关键变化列出可追踪因果链（例如出口管制→合法供给下降→企业利润变化→下一轮游说压力）。
4. **结局页**：阵营的多维绩效、重要转折点、政策后果与结局标签；基础重开。**回滚/反事实重玩为P2**，不影响P0交付。

## 9. 验收标准：程序正确性 + 游戏性

### P0：没有以下结果不得进入UI精修

- [ ] 两个玩家阵营都可独立进行**完整六轮**，游戏不用LLM也能跑通。
- [ ] 九个Agent有不同目标、行动范围和实际自主动作；韩国、荷兰/日本设备、TSMC与企业经营模块确实影响结算。
- [ ] 非法贸易/越权政策在验证阶段被拦截；预算/AP不足的动作无效。
- [ ] 当其他条件保持不变，收紧受控芯片合法出口条件不会让该**受控交易**合法交付量增加。
- [ ] 设备新增交付受限不自动删除既有设备；设计/制造/封装/HBM不互相替代。
- [ ] 政府拨款与企业到账一致；企业投资扣现金、按延迟生效；利润与库存不会凭空重复增加。
- [ ] 镓锗仅冲击相应材料用途，短期库存及长期替代起作用；美国AI芯片制造不被无依据地直接扣产量。
- [ ] 相同初态、动作序列及随机输入得到完全相同的引擎数值结果；每轮记录完整动作及状态差分。
- [ ] 至少一轮出现“企业收益→政府压力→后续政策/策略变化”的反馈；第三方有独立拒绝配合的空间。

### P1：若时间允许

- [ ] 至少一个LLM对手经结构化输入选择合法动作，并在无效/超时情况下自动降级。
- [ ] 至少三局试玩，检验“永远最严格管制/永远最大补贴”不会在所有剧本或偏好下无成本最优。
- [ ] 结局解释基于规则日志，画面可读、无主要状态错位。

### P2：仅在交付稳定后

- [ ] 存档与回到某轮继续；复杂反事实双分支对比、自由谈判和所有角色LLM化不要求本次完成。

| 隐藏偏好与策略互动 | 不完全信息、重复博弈、Stackelberg等文献提供抽象框架 | 各角色的隐藏偏好类型、效用系数、信号更新分数 |

**文献不能证明的，不得以“实测现实参数”表述。** 某些项目资料属于AI生成综述，应优先以其中可追溯的一手论文、官方政策与企业财报为依据。现实政策会发生变化，游戏开局为**架空近未来**，因此不得把某一历史时点的禁止令误写成今天无例外的现行法律。

> 可用于作品说明的一句话：本作依据公开产业研究与政策资料抽象多方竞争及合作机制；政策等级、利益权重、动态系数和事件概率均为明确标记的游戏设定；LLM负责部分角色的策略判断与解释，数值后果由统一的规则引擎计算；作品供互动探索，不构成现实预测。

### 不再悬而未决的四项架构选择

1. **最终角色数：九个**，不再回退到v2的八个，也不把ASML、韩国存储、台湾地区政策管理方在MVP中升级为新增Agent。
2. **代码语言：TypeScript单栈**，可选模型后端代理，不同时构建两套独立经济引擎。
3. **对局核心：规则引擎先行**，LLM是可替换决策器而非经济结算器。
4. **研发目标：可玩性与机制可解释性**，不是政策效果实证识别或真实未来预测。
