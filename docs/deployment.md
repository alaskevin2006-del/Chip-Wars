# Isolated deployment and rollback

Run `bash ops/preflight.sh` on the target before any installation. It lists listeners, running services, free disk, runtime and container names without reading project secrets. Candidate port: 4187; do not use if occupied by another service. Use `$HOME/chip-wars`, a new `chip-wars.service`, and a single `chip-wars` container with app label. No default nginx changes, no 80/443 binds, no global restarts/upgrades or firewall disabling.

The target can use its existing Docker daemon with a separate official Node 22/24 runtime. The deployment script never installs Node globally or changes existing images/containers. Read-only app mount, unprivileged container uid, no extra capabilities, bounded memory/CPU/PIDs, independent writable quota ledger. Pin `CHIP_WARS_NODE_IMAGE` to an already verified official Node digest for reproducible production rollouts. No npm dependencies are required by the built-in Node server.

Before deployment: typecheck, tests, build; confirm reviewed source commit and CI. Package ONLY `dist/`, `server/`, `ops/`, and a `VERSION` file in a gzip tar archive named `chip-wars-<git-sha>.tar.gz`. Transfer to `/tmp/` via authenticated SFTP; do not include .env, .git, chat transcripts or node_modules. Copy deployment script to a separate `/tmp/chip-wars-deploy.sh` or invoke the packaged script after validating extraction paths. Run `bash /tmp/chip-wars-deploy.sh /tmp/chip-wars-<sha>.tar.gz <sha> 4187`.

Create `$HOME/.config/chip-wars/environment` with mode 600, parent mode 700, using an encrypted transfer or interactive secure input. Never put secrets in argv, shell history, repo, logs, frontend `VITE_*` variables or deployment output. Variables: `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL=https://api.deepseek.com`, `DEEPSEEK_MODEL=deepseek-flash`, `HOST=0.0.0.0`, `PORT=4187`, `PUBLIC_ORIGIN` (actual public origin), `LLM_DAILY_LIMIT=60`, `LLM_LEDGER_PATH=/state/llm-usage.json`. If API key is absent the rules game stays functional. The usage ledger must be on the separate persistent runtime mount so service restarts cannot reset daily provider allowance. Provider account budget is an additional ceiling, never the sole protection.

Scripts only stop/start the named Chip-Wars unit. Releases are immutable named directories; `current` and `previous` links identify deployed versions. A failed health check restores the prior Chip-Wars release. Repeating a deployment of the same version reuses its artifacts. No previous release: failure stops only Chip-Wars and keeps the failed release for diagnosis. Roll back with `bash "$HOME/chip-wars/current/ops/rollback.sh"`. Stop/start with `sudo systemctl stop chip-wars.service` / `sudo systemctl start chip-wars.service`. Check `systemctl status chip-wars.service` and `curl -f http://127.0.0.1:4187/api/health`.

Validate after installation: public homepage and each referenced asset; both player roles through six rounds; model unavailable fallback; no secret patterns in built assets, API response, tracked history or service logs; previous container IDs, health/status, restart counts and public endpoints stay available. Record actual deployed SHA separately from documentation commits. External reachability requires an actual request from outside the host; successful localhost health does not prove Tencent Cloud security-group access.

Open only the new TCP port in Tencent Cloud's security group if required; preserve existing rules and OS firewall. Cloud API access might be unavailable, in which case report blocked external reachability. HTTP is temporary: it does not encrypt play traffic. Before broader publication add domain HTTPS via a separate approved route without replacing default sites. Same-origin/rate/concurrency/daily limits reduce proxy abuse but are not authentication; keep the daily ceiling small and monitor actual spend. Do not print private provider response bodies.
